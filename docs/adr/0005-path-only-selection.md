# ADR-0005 — `$name` 只注入路径，体量预算随之退役

## 背景

ADR-0001 原定 `$name` 选中后送入整篇 body，ADR-0004 因此需要"体量预算"来兜住超长 body。用户改变了这条：选中只注入路径即可。

pi 在系统提示里本来就给出每个 skill 的名称、描述与路径（模型据此解析 skill 内的相对资源），所以整篇注入等于替模型做一次它自己会做的读取，代价是把去重、截断、快照这一整条链都变成必需品。

## 决定

- `$name` 命中后只向本轮上下文注入该 skill 的 `SKILL.md` 路径，附一句让模型按需读取。
- 不注入 body，因此不需要体量预算；ADR-0004 的 B 项退役。
- 去重降级为提示：同一分支已点名过就回报"已点名"，不重复送路径。

## 被否决的选项

- **整篇注入（broker 的做法）**：内容确定性强，但连带压迫出三条机制——去重、截断、快照一致性，而它们的根源都是"把内容提前搬进对话"。
- **注入截断版 body**：截断后的内容既不是原文也不是路径，最容易被误解成"这个 skill 就这么点内容"。
- **路径 + 首段摘要**：多一次生成调用，且首段常是 frontmatter 说明，信息密度最低。

## 后果

- `$name` 的价值从"传送内容"变成"精确点名"：把被偏好隐藏或降权的 skill 唤回视野，或强调本轮优先用它。它与偏好层的 hidden/weight 互补。
- 使用统计仍然按"被点名次数"计，与 body 是否被读无关。
- 模型仍需自己 `read` 路径；路径写错或文件被移动时，本插件能立刻发现（扫描期已持有路径），而注入 body 的方案只能在读取时才发现。
