# ADR-0003 — 偏好存成单一文件里的稀疏条目

## 背景

偏好是对一张 skill 表的微调：多数 skill 没有偏好，少数 skill 只改一两个字段。用户还需要项目级覆盖（同一个 skill 在 A 项目用中文、在 B 项目用英文）。

## 决定

- 用户级：agent 目录下一份 `skillbutler.yml`，键是 skill 名，值是稀疏条目，只写与默认不同的字段。
- 项目级：`.pi/skillbutler.yml`，同结构，按键与字段覆盖用户级。
- 偏好只写在 YAML 里，不回写 `SKILL.md` 的 frontmatter。

## 被否决的选项

- **每个 skill 一个文件**：无法一眼看出冲突与遗漏，且和 skill 目录形成两套清单。
- **写进 frontmatter `metadata`**：会改动别人的 skill 文件（package 自带、git 管理、同步），而且同一偏好会有两处真相。
- **合并成数组按顺序匹配**：同名的两个条目谁生效要靠顺序，而顺序会在编辑器里被静默改动。

## 后果

- 需要一个"重名"诊断：托管根内同名 skill 按 pi 原生规则保留先发现的，并在诊断里报告后者被忽略。
- 未托管 skill 的条目被忽略，诊断需说明原因。
- 项目级文件只覆盖提供的字段，不提供"删除用户级偏好"的语法，除非后续确有需求。
