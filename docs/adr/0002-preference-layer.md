# ADR-0002 — 偏好层改写每轮系统提示的 skill 清单

## 背景

pi 在启动时把每个 skill 的 `name`、`description`、`path` 放进系统提示，body 只在模型主动读取时进入上下文。`before_agent_start` 事件暴露可变的 `systemPromptOptions.skills`（`Skill[]`），并在每轮请求前把变化以 section 补丁的形式追加。

## 决定

偏好在每轮 `before_agent_start` 里改写 `systemPromptOptions.skills`：

- 过滤：偏好标记为不可见的 skill 从清单移除。
- 排序：按偏好里的权重重排，让该用的排前面。
- 改写描述：把语言、写作风格这类约定压缩进描述末尾。

另外附加一条限长的**总览**，说明当前生效的偏好。每 skill 的细则文本留到 v2。

## 被否决的选项

- **每 skill 注入一段指引（只做消息层）**：N 条常驻文本会随 skill 数量线性增长，与刚决定要做的体量预算自相矛盾。
- **只筛选不改写描述**：模型对"什么时候该用"的判断来自 description；不改写就管不住语言与风格这类偏好。
- **用 `systemPrompt` 整体替换**：会绕过 pi 的 section diff，每次变化都是整段缓存失效。

## 后果

- 偏好只影响"模型看见什么"，不修改对话历史，因此回合之间可逆。
- 总览长度必须有硬上限，否则它会变成第二个常驻提示。
- 需要每轮构建并比对清单，属于纯本地计算，不产生模型请求。
